# bismar-crm

Внутренняя CRM: база знаний с ИИ-консультантом по её материалам, аналитика продаж и мессенджер сотрудников. Laravel-API и Nuxt-приложение лежат в одном репозитории — `back/` и `front/`.

## Что внутри

**Доступ.** Вход по сессионной куке через Laravel Sanctum. Ролей как понятия нет: у человека одно из трёх положений (`AccessLevel` — суперадминистратор, администратор, пользователь), первые два проходят `Gate::before` целиком, обычному пользователю права выдаются по одному. Правила, которым подчиняются сами администраторы — назначать администраторов может только суперадминистратор, понизить себя нельзя, один суперадминистратор обязан остаться, — живут в `App\Actions\User\SyncUserAccess`, а не в политике: `Gate::before` политику не спрашивает.

**База знаний.** Категория → курс → модуль → урок. Статьи набираются в TipTap, записи и вложения уходят в S3, прогресс и результаты тестов считаются по каждому сотруднику. У курса три отдельных списка людей: автор, допущенные и ответственные — последним пишут, когда написанного не хватило.

**Расшифровки и таблицы ответов.** У каждой единицы содержания урока — записи, файла, блока статьи — есть текстовая расшифровка; читателю она не видна и нужна поиску. Расшифровка блока статьи выводится из его собственного текста, если её не загрузили. Поверх расшифровок автор ведёт таблицу «вопрос → ответ → точное место».

**Консультант.** Отвечает на вопросы сотрудников строго по опубликованным материалам. Ищет сначала по таблицам ответов, потом по расшифровкам; кандидатов отбирает полнотекстовый поиск Postgres, переранжирует необязательная модель эмбеддингов. Ответ приходит со ссылками на источник — вплоть до секунды записи, страницы документа или блока статьи, — и ссылки проверяются по тому, что действительно было отправлено модели. Помнит последние круги разговора и достраивает по ним неполный вопрос перед поиском. Когда прямого ответа нет, показывает близкое по теме и карточку ответственного за курс. Каждый вопрос попадает в журнал, где автор курса видит, на чём консультант споткнулся, и может ответить — ответ становится строкой таблицы и приходит сотруднику в тот же разговор.

**Аналитика.** Дашборд продаж, клиентов и товаров поверх витрины ClickHouse, которую наполняет ночная выгрузка из 1С. Доступ только на чтение.

**Мессенджер.** Личные и групповые переписки сотрудников в реальном времени через Laravel Reverb: непрочитанное, «печатает…», «в сети», вложения.

Продажного домена — контактов, компаний, сделок — пока нет: имена прав под них в `Permission` заведены, но ни таблиц, ни эндпоинтов за ними не стоит. Подтверждение почты и сброс пароля тоже не сделаны, почтовик остаётся `log`.

## Установка

Нужны PHP 8.3+, Composer, Node 20+ и PostgreSQL. Базы — рабочая и тестовая:

```sql
CREATE DATABASE bismar;
CREATE DATABASE bismar_testing;
```

API:

```bash
cd back
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
```

Приложение:

```bash
cd front
npm install
```

### Что заполнить в `back/.env`

Приложение поднимется и с пустыми ключами — соответствующий раздел просто отключится, а не сломает остальное. Все переменные описаны прямо в `.env.example`.

- `DB_*` — подключение к PostgreSQL.
- `AWS_*` — S3 для вложений уроков. Для Selectel и других S3-совместимых хранилищ нужны `AWS_ENDPOINT` и `AWS_USE_PATH_STYLE_ENDPOINT=true`.
- `ANTHROPIC_API_KEY` **или** `ANTHROPIC_AUTH_TOKEN` — консультант. Без ключа страница честно отвечает, что недоступна.
- `AI_EMBEDDING_MODEL` — поиск по смыслу и дословная выдача готовых ответов. Пусто — поиск остаётся словесным.
- `CLICKHOUSE_*` — сервер аналитики.
- `REVERB_*` — сокет-сервер мессенджера.

Фронтенду хватает значений по умолчанию из `nuxt.config.ts`; переопределяются они через `NUXT_PUBLIC_API_BASE` и `NUXT_PUBLIC_REVERB_KEY` / `_HOST` / `_PORT` / `_SCHEME`.

## Запуск

```bash
cd back  && php artisan serve --port=8100
cd front && npm run dev            # http://localhost:3100
```

Порт 3000 намеренно оставлен свободным. Сеяный вход — `admin@bismar.test` / `password`.

Мессенджеру нужен отдельно запущенный сокет-сервер:

```bash
cd back && php artisan reverb:start
```

Без него приложение работает, но чужое сообщение появляется только после обновления страницы. В боевом развёртывании держите его под supervisor и пробрасывайте снаружи как `wss`.

Пересобрать всё, по чему ищет консультант, — выведенные расшифровки, имена блоков, векторы:

```bash
cd back && php artisan lms:reindex
```

## Тесты

```bash
cd back && composer test
```

Тесты идут по PostgreSQL (`bismar_testing`, прописана в `phpunit.xml`), не по SQLite: подмена сломала бы проверки поиска по русскому тексту.

## Устройство

```
back/app/
  Actions/      бизнес-операции — по классу на операцию
  Data/         объекты передачи данных
  Enums/        права, положения доступа, исходы консультанта
  Http/         контроллеры, form-request'ы, ресурсы, middleware
  Models/       Eloquent-модели
  Policies/     права на объект
  Support/      Ai, Analytics, Chat, Lms — механика, не привязанная к HTTP
front/app/
  components/   компоненты интерфейса
  composables/  обёртки над API и сокетами
  pages/        маршруты
```

Контроллеры остаются тонкими: проверка — в form-request, операция — в классе `Actions`, ответ — в ресурсе.

## Что стоит знать, прежде чем править

- **Права привязаны к гарду `web`** через константу `App\Support\Authorization::GUARD`. Не возвращайте сюда `config('auth.defaults.guard')`: `auth:sanctum` переписывает эту настройку прямо посреди запроса, и все не-администраторы молча остаются без единого права. Администраторы ошибку не показывают — их пропускает `Gate::before`.
- **Базы созданы с сортировкой `C`**, и `lower()` в ней сворачивает только латиницу. Любой поиск без учёта регистра по русскому тексту обязан идти через `COLLATE "und-x-icu"` — образец в `scopeMatching` у `App\Models\Course`.
- **Выражение полнотекстового поиска обязано совпадать с выражением GIN-индекса**, иначе Postgres индекс не возьмёт. Нормализация текста — одна на всех, в `App\Support\Ai\RussianText`.
- **Пороги консультанта откалиброваны на `text-embedding-3-small`.** На другой модели эмбеддингов шкала другая — перемеряйте, а не подгоняйте на глаз.
- **`Storage::fake` зеленит загрузки даже без установленного flysystem-адаптера.** После правок настроек хранилища сделайте один настоящий обмен с бакетом.
- **В ClickHouse квалифицируйте имена колонок таблицей.** Неквалифицированное имя может разрешиться не в ту сторону, и агрегат молча посчитает бессмыслицу.

Интерфейсные надписи и доменные комментарии — по-русски, докблоки уровня фреймворка — по-английски.
