# Увольнения и выходные интервью

В карточке сотрудника «Уволить» открывает выбор:

- «Выслать анкету»: создаётся выходная анкета; до её отправки доступна только она.
- «Не прошёл стажировку»: причина `probation-failed`, анкета не создаётся, вход закрывается сразу.

API и MCP принимают `survey_action: send | failed-internship`. Если параметр отсутствует, сохраняется прежнее поведение `send`. При восстановлении сотрудника незаполненная анкета отменяется. Отменённые анкеты предыдущего увольнения не становятся активными при новом увольнении без анкеты.

## Отчёт

Блок «Аналитика увольнений» находится в «Аналитика → Штат» и использует общий период и фильтры. GET/PUT `/api/analytics/staff/dismissals`. Область видимости определяется существующим `StaffScope`; ручной ввод дополнительно требует `users.manage`. Свободные формулировки из анкет доступны только с этим правом.

Источник увольнений совпадает с отчётом о штате: текущие кадровые записи, у которых дата увольнения попадает в период. Восстановленные и удалённые записи не считаются уволенными. Для интервью берётся последняя неотменённая анкета именно этого увольнения, а не прошлого цикла работы. Интервью считается завершённым при заполнении анкеты; статус берётся на момент просмотра отчёта.

- Охват интервью = заполненные анкеты / уволившиеся × 100%.
- Доля удерживаемых = вручную указанное количество / прошедшие интервью × 100%.
- Ранний уход = увольнение ранее трёх календарных месяцев от даты приёма. На границе трёх месяцев увольнение уже не раннее. Записи без даты приёма учитываются отдельно.
- Доля ранних уходов = ранние уходы / все уволившиеся × 100%.
- Причины оформления увольнения группируются по кадровому справочнику, включая «Причина не указана»; доля — от всех увольнений.
- Формулировки причин из анкет показываются отдельно. Совпадающие тексты объединяются без учёта регистра и лишних пробелов; смысловая классификация не выполняется.
- Текучка подразделения = уволившиеся / ручная среднесписочная × 100%.

Нулевой знаменатель и отсутствующий ручной ввод показываются «—». Ноль, введённый вручную, сохраняется как ноль. Число удерживаемых не может превышать число интервью. Подразделения показаны раскрывающимся деревом структуры. Родительская строка включает всю свою ветку; сотрудник в нескольких дочерних отделах учитывается в итоге родителя один раз. Ручная среднесписочная и удерживаемые задаются отдельно для каждой строки с учётом её ветки. Поиск раскрывает путь к найденному отделу; свёрнутые строки не теряют ручные значения при сохранении.

Ручные данные: количество удерживаемых, оценка условий (свободное поле), среднесписочная и удерживаемые по подразделениям. Они хранятся в `staff_dismissal_report_inputs` отдельно для каждой комбинации периода, разрешённых подразделений, должности, режима работы и тегов, доступны между сессиями. Записывается автор последней правки.

Указанный заказчиком Excel-шаблон прикреплён к материалу `analitika-uvolnenii` через Google Drive, но требует отдельного входа Google. Точные формулы и шкала оценки из файла пока не сверены. Выбранные формулы и единицы измерения явно подписаны в интерфейсе.

## Повторное трудоустройство

При увольнении в форме явно выбирается «Да» или «Нет» для `rehire_recommended`; этот выбор независим от назначения выходной анкеты. Для старых увольнений и старых API-клиентов без этого параметра значение остаётся `null` («Не указано»). Отметка видна рядом со статусом увольнения в карточке и в списке сотрудников. Администратор может изменить решение для уволенного сотрудника через PUT `/api/users/{user}/rehire-recommendation`; действуют те же ограничения уровня администратора, что и при увольнении. Хранятся автор и дата последнего решения. Восстановление сбрасывает отметку для нового периода работы; снимок в старой анкете сохраняется.

Отчёт считает «Да», «Нет» и «Не указано» отдельно, включая показатели по веткам подразделений. GET `/api/analytics/staff/dismissals/rehire` отдаёт отдельный список рекомендованных с теми же периодом и областью доступа, поиском и пагинацией по 25 записей. ФИО не включаются в запрос общей статистики. Список доступен в конце отчёта и загружается при раскрытии.

В окне ручного ввода видны редактируемые даты «С» и «По». После их изменения нужно загрузить период: форма получает сохранённые значения и актуальные ограничения именно для этих дат. До загрузки сохранение заблокировано. После сохранения новый период применяется к основному отчёту. Старые значения другого периода не перезаписываются.
